# DealerPilot AI — Sprint 7
## App-Controlled Marketplace Automation

Sprint 6 is complete.

Goal:
Move publishing control from the Chrome Extension popup into the DealerPilot web app.

The extension should become a background execution bridge.
The operator should control publishing from DealerPilot, not from the popup.

Do NOT auto-click Facebook's final Publish button.
The extension fills the form and stops for human review.

--------------------------------------------------
CORE FLOW
--------------------------------------------------

DealerPilot App
→ Marketplace AI / Publishing Queue
→ Operator clicks “Publish with Extension”
→ Backend assigns job to online extension
→ Extension detects assigned job
→ Extension opens Facebook Marketplace create vehicle page
→ Extension claims job
→ Extension fetches payload
→ Extension fills the form
→ Extension reports “Ready for Review”
→ Operator manually clicks Publish on Facebook
→ Operator returns to DealerPilot or extension panel to mark Published / Failed
→ DealerPilot stores result

--------------------------------------------------
REQUIREMENTS
--------------------------------------------------

1. App-Controlled Publishing

On /marketplace-ai or the publishing queue tab:

Add:
- Publish with Extension button per queued job
- Start Assisted Publishing button for next ready job
- Bulk Publish Selected button

When clicked:
- validate job.id exists
- validate an online extension is available
- assign job to extension
- set job status to ASSIGNED or WAITING_FOR_EXTENSION
- show live status in the UI

Do not depend on the popup button to start production publishing.

--------------------------------------------------

2. Extension Bridge Mode

Chrome extension should poll backend for assigned jobs.

Popup behavior:
- Status only
- Debug only
- Hide “Start Publishing Job” under Debug Mode
- Main operator flow should happen from the app

Extension behavior:
- poll assigned jobs
- if assigned job exists:
  - open Facebook Marketplace create vehicle page if not already open
  - claim the job
  - fetch payload
  - run existing state machine
  - fill the form
  - stop before final Publish
  - report READY_FOR_REVIEW

Keep existing form-filling state machine from v1.0.7.
Do not rewrite field filling.

--------------------------------------------------

3. Fix Job ID Contract

Current bug:
POST /api/publishing/jobs/undefined/claim failed: 500

Fix this permanently.

Requirements:
- Never call claim with undefined.
- Log full next-job response if id missing.
- Add backend validation: invalid job id returns 400, not 500.
- Ensure extension reads job id correctly from backend response.
- Support response shapes safely:
  { job: {...} }
  { data: { job: {...} } }
  { jobs: [...] }
